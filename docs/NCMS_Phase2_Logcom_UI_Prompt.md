당신은 이 프로젝트의 고객용 웹사이트를 구현하는 시니어 프런트엔드 개발자이자 UI 디자이너입니다. 아래 지시를 읽고 현재 저장소에서 실제 화면 구현과 검증까지 진행하세요.

**1. 프로젝트 상황과 이번 작업의 목표**

- 프로젝트 이름은 NCMS(NameCard Management System)이며, 고객에게 보여줄 서비스 브랜드는 로그컴(LOGCOM)입니다. 투비더원은 개발사이므로 고객용 화면의 브랜드로 사용하지 마세요.
- 1페이즈 어드민은 이미 운영 중이고 안정화되었습니다. 2페이즈는 일반 고객용 홈페이지입니다.
- 기본 폴더·패키지·레이어 구조는 이미 만들어져 있습니다. 현재 구조를 먼저 확인하고 그 안에서 구현하세요.
- 로그컴으로부터 공식 로고, 브랜드 가이드, 사진, 상품 콘텐츠를 아직 받지 못했습니다. 주문·결제 등 세부 기능과 운영 정책도 아직 확정되지 않았습니다.
- 이번 목표는 로그컴 담당자가 PC와 모바일에서 직접 둘러보며 디자인과 콘텐츠 방향을 검토할 수 있는 고객용 홈페이지 시안입니다. 한국어 카피와 자체 제작 명함 비주얼을 포함한, 완성도 있는 프런트엔드 프로토타입을 만드세요.
- 아래 메뉴·상품 분류·문구·색상은 이번 디자인 시안을 위한 제안입니다. 확정 요구사항이나 실제 로그컴의 영업 정보로 취급하지 마세요.

**2. 먼저 현재 프로젝트를 확인하세요**

- 저장소의 작업 지침, 현재 변경사항, 고객용 앱 위치, 실행 스크립트, 라우팅, 스타일링 방식, 공통 컴포넌트, 기존 에셋을 확인하세요.
- 기존 프레임워크·패키지 매니저·레이어 규칙을 따르세요. React 프로젝트를 임의로 Next.js로 바꾸거나, 새 저장소·별도 중첩 프로젝트를 만들지 마세요.
- 실제 로그컴 자산으로 확인되는 로고·폰트·컬러가 있으면 우선 활용하세요. 어드민의 화면 레이아웃을 고객 홈페이지에 그대로 사용하지는 마세요.
- 기존 작업을 덮어쓰거나 대규모 폴더 이동·불필요한 의존성 추가를 하지 마세요. 고객용 앱과 필요한 최소 범위만 수정하세요.
- 고객용 앱의 위치를 특정할 수 없다면 어드민을 임의로 수정하지 말고 그 경로만 확인 요청하세요.
- 시작할 때 발견한 구조와 수정 범위를 짧게 설명한 뒤 구현을 계속하세요. 계획서만 작성하고 멈추지 마세요.

가능하면 다음 공개 페이지를 읽기 전용으로 살펴보세요.

- 일반명함 상세: https://www.printrobo.co.kr/products/economy-business-cards/
- 기업명함 소개: https://www.printrobo.co.kr/corporate/
- 고객센터: https://www.printrobo.co.kr/help/

참고할 핵심은 명함 종류별 탐색, 제품 이미지와 설명의 배치, 제작 가이드, 일반 고객과 기업 고객의 진입 경로입니다. 상품 상세에는 옵션·견적·파일 안내가 있고 기업 서비스 소개가 별도로 있다는 정보 구조를 이해하세요. 옵션·견적·업로드의 실제 구현은 이번 범위가 아닙니다.

디자인은 로그컴용으로 새롭게 구성하세요. 프린트로보의 로고·이미지·고유 문구·가격·정책·HTML/CSS를 복제하지 마세요. 회원가입·로그인·장바구니 담기·파일 업로드·문의 제출·주문·결제는 하지 마세요. 사이트에 접근하지 못하면 위 요약을 기준으로 작업하고, 확인하지 않은 화면을 확인했다고 보고하지 마세요.

**4. 디자인 방향**

명함과 종이의 질감이 중심인, 신뢰감 있고 정돈된 한국 인쇄서비스 홈페이지를 만드세요. 상품을 쉽게 살펴볼 수 있으면서 기업 고객에게도 어울리는 톤이어야 합니다.

공식 가이드가 없을 때 적용할 임시 디자인 기준:
- 브랜드 표기: 읽기 쉬운 LOGCOM 텍스트 워드마크. 공식 로고로 확정하지 않습니다.
- 기본색: 딥 네이비 #17324D, 강조색 #245EDB.
- 배경: 흰색과 따뜻한 아이보리 #F5F3EE. 본문은 대비가 충분한 짙은 회색.
- 타이포그래피: 기존 한국어 폰트를 우선 사용하고, 없으면 한국어 시스템 폰트와 적절한 대체 폰트를 사용합니다.
- 데스크톱 콘텐츠 폭은 약 1200~1280px를 기준으로 하되, 기존 레이아웃 규칙과 화면 크기에 맞춥니다.
- 큰 상품 비주얼, 분명한 제목, 읽기 편한 설명, 얇은 구분선, 절제된 그림자를 사용합니다.
- 히어로·상품 그리드·넓은 기업 서비스 배너 등 섹션별 구성을 달리해 단조로움을 줄입니다.
- 과도한 그라데이션, 유리 효과, 이모지 아이콘, 의미 없는 움직임, 큰 빈 공간, 관리 대시보드 같은 UI는 피하세요.
- 고객 화면에 NCMS 내부 용어, API 연결 예정, DB 연동 대기 같은 개발 설명을 넣지 마세요.

**5. 이번에 구현할 페이지**

아래 경로는 예시이며 기존 라우터 규칙을 우선합니다. 모든 페이지는 공통 헤더·푸터·디자인 토큰을 사용하세요.

A. 홈 /
- 헤더: LOGCOM, 명함 둘러보기, 기업명함, 제작 가이드. 모바일에서는 접고 펼칠 수 있는 메뉴.
- 히어로: 큰 명함 목업과 아래 카피를 사용하되, 화면에 맞게 줄바꿈과 문장을 다듬으세요.
  - 제목: “좋은 인상을 남기는, 한 장의 명함”
  - 설명: “다양한 명함 스타일과 제작 정보를 로그컴에서 살펴보세요.”
  - 주요 버튼: “명함 둘러보기” → 상품 목록
  - 보조 버튼: “기업명함 알아보기” → 기업명함 소개
- 명함 스타일 소개: 기본형·고급지·텍스처·포인트 후가공의 네 가지 예시 분류.
- 명함 스타일 카드: 총 6개 정도의 샘플을 만들고, 서로 다른 자체 제작 목업과 짧은 설명을 배치하세요. 판매 실적을 암시하는 베스트·인기순·판매량 배지는 사용하지 마세요.
- 소재와 표현 소개: 매끈한 표면, 자연스러운 종이 질감, 부분적인 광택처럼 디자인을 비교할 수 있는 시각 콘텐츠.
- 기업명함 배너: 여러 구성원의 명함이 일관된 스타일로 배열된 비주얼과 기업명함 소개 페이지 링크.
- 제작 가이드 미리보기: 앞뒷면 정보 정리, 가독성, 시안 확인 등 3개의 도움말.
- 푸터: 브랜드명과 실제 구현된 메뉴. 회사 정보가 없다고 사업자번호·주소·전화번호·이메일을 임의로 채우지 마세요.

B. 명함 목록 /cards
- 예시 분류 탭과 상품 그리드를 구현합니다.
- 탭을 누르면 로컬 샘플 데이터가 필터링됩니다.
- 상품 카드를 누르면 해당 상세 페이지로 이동합니다.
- 상품명·설명·이미지는 표시하되, 미확정 가격을 0원이나 가짜 판매가격으로 표시하지 마세요.

C. 명함 상세 /cards/:slug
- 큰 제품 비주얼, 썸네일 또는 앞뒷면 전환, 상품명, 짧은 스타일 설명을 배치합니다.
- 소재 표현과 레이아웃을 살펴볼 수 있는 상세 콘텐츠를 만듭니다.
- “다른 명함 보기”, “제작 가이드 보기”처럼 실제 동작하는 링크를 사용합니다.
- 수량·재질 선택에 따른 견적 계산, 주문 양식, 결제, 파일 업로드는 구현하지 않습니다.
- 존재하지 않는 상품 경로는 안내 화면과 목록 복귀 링크로 처리합니다.

D. 기업명함 /business
- 일관된 명함 디자인과 구성원별 정보 정리라는 주제를 시각적으로 소개합니다.
- 팀 명함 목업, 서비스 방향 소개, 확인할 정보에 관한 안내를 구성합니다.
- 기존 소스·문서에서 확인되지 않은 총무 승인, 자동 정산, ERP 연계 등의 기능을 제공 중이라고 홍보하지 마세요.
- 실제 문의처가 없으면 상담 접수 폼을 만들지 말고 “명함 스타일 보기”, “제작 가이드 보기”로 연결하세요.

E. 제작 가이드 /guide
- 명함에 넣을 정보, 작은 글씨의 가독성, 앞뒷면 구성, 최종 시안 확인에 관한 짧은 한국어 안내를 작성합니다.
- 소수의 FAQ를 아코디언으로 구현하세요.
- 제작기간·배송비·취소·환불·업로드 규격 등 로그컴의 확정 정책이 필요한 답변은 만들지 마세요.
- 업체가 제공하지 않은 이용약관이나 개인정보처리방침을 완성된 정책처럼 작성하지 마세요.

로그인·회원가입·장바구니·주문내역 화면은 이번 작업에 추가하지 않습니다. 프린트로보에 있다는 이유만으로 명함 외의 스티커·배너·판촉물까지 상품 범위를 확대하지 마세요.

**6. 제공받은 이미지 없이도 비주얼을 완성하세요**

회색 빈 박스나 깨진 외부 이미지로 끝내지 마세요. 모든 주요 영역에 실제로 표시되는 원본 비주얼을 마련하세요.

- 최소 구성: 히어로용 명함 장면 1개, 6개 샘플 상품의 대표 비주얼, 기업명함용 팀 구성 장면 1개.
- 동일한 촬영·조명·배경 톤을 유지하면서 종이색, 타이포그래피, 배치, 질감은 상품별로 구분하세요. 일부 목업 구성을 재사용하더라도 모든 카드가 같은 이미지처럼 보이지 않게 하세요.
- 이미지 생성 기능이 있으면 실제 종이 명함을 촬영한 듯한 비주얼을 새로 만들 수 있습니다. 실제 로그컴의 납품 사례나 제품 사진이라고 표시하지 마세요.
- 이미지 생성 기능이 없으면 자체 SVG 또는 HTML/CSS로 명함 앞뒷면, 종이 두께, 겹침, 부드러운 접지 그림자를 표현하세요. 외부 이미지 확보를 기다리며 작업을 멈추지 마세요.
- 한글 문구는 가능한 한 HTML/SVG 텍스트로 또렷하게 배치하고, 생성 이미지 안의 깨진 글자를 그대로 사용하지 마세요.
- 목업에는 LOGCOM, SAMPLE STUDIO 등 예시임을 알 수 있는 이름을 사용하고, 실존 고객 로고·이름·연락처를 넣지 마세요.
- 검색 결과 이미지, 경쟁사 이미지, 라이선스가 불분명한 스톡 이미지를 임의로 다운로드하거나 외부 URL로 직접 연결하지 마세요.
- 재사용할 비주얼은 프로젝트 안의 에셋 또는 컴포넌트로 관리하세요. 외부 이미지 서비스가 없어도 화면이 완성되어야 합니다.

이미지 생성 기능을 사용할 경우의 방향 예시:
“따뜻한 아이보리 배경 위에 정돈된 네이비와 흰색 명함 여러 장, 실제 종이의 미세한 질감과 단면 두께, 부드러운 측면 자연광과 접지 그림자, 한국의 전문 인쇄서비스에 어울리는 절제된 제품 사진, 텍스트와 로고를 추가할 여백, 사람·전자기기·워터마크 없음.”

히어로 장면은 가로형, 상품 대표 비주얼은 동일한 비율로 맞추세요. 일반 사무실·악수 사진으로 명함 이미지를 대체하지 마세요.

**7. 임시 콘텐츠와 실제 정보의 구분**

- 이 안내의 노출은 한곳에서 관리하고, 실제 콘텐츠 검토 후 제거할 수 있게 하세요. 이번 시안에서는 켜 둡니다.

- 가격·납기·연락처·정책처럼 검증이 필요한 정보는 데이터에서 미확정 상태로 관리하고, 화면에는 불필요한 항목을 숨기세요.
- 각종 문구와 이미지 경로를 여러 컴포넌트에 흩어두지 마세요. 기존 레이어 규칙에 맞는 콘텐츠·샘플 데이터 파일에서 교체할 수 있게 구성하세요.
- 별도 문서에 임시 로고·카피·상품 분류·이미지·운영 정보 중 무엇을 나중에 교체하거나 확인해야 하는지 정리하세요.

**8. 이번에 허용할 동작과 제외할 동작**

구현할 동작:
- 페이지 이동, 모바일 메뉴, 카테고리 필터, 이미지 전환, FAQ 열기·닫기, 목록 복귀.
- 로컬 데이터와 화면 상태만으로 동작하게 구현하세요.
- 모든 주요 버튼에 실제 이동이나 UI 반응이 있어야 합니다. href="#"나 alert만 연결한 버튼은 사용하지 마세요.

이번에 구현하지 않을 것:
- 인증, 회원가입, 실제 주문·장바구니·결제·견적 계산.
- 파일 업로드, 메일·SMS 발송, 상담 접수, 분석·추적 서비스 연동.
- 백엔드 API·DB 스키마·마이그레이션·어드민 기능의 변경.
- Vercel·Railway 운영 설정 변경, 운영 배포, git push.

현재 고객용 앱에 공용 API 호출 코드가 있더라도 시안 페이지는 운영 API에 요청하지 않게 하세요. 실제로 저장·접수하지 않았는데 “주문 완료”, “상담 접수 완료” 같은 성공 메시지를 표시하지 마세요. 추후 기능 연결을 위해 불필요한 가짜 API 서버나 복잡한 추상화 계층을 만들 필요는 없습니다.

**9. 품질과 검증 기준**

- PC·태블릿·모바일에서 모두 확인하세요. 최소 375px, 768px, 1440px 폭을 점검합니다.
- 좁은 화면에서 가로 스크롤, 제목 잘림, 버튼 겹침, 너무 작은 터치 영역이 없어야 합니다.
- 키보드로 메뉴·탭·FAQ를 사용할 수 있어야 하고, 포커스 표시와 적절한 접근성 속성을 적용하세요.
- 정보 이미지에는 적절한 대체 텍스트를 넣고 장식용 이미지는 중복 낭독을 피하세요.
- 색상 대비, 본문 가독성, 명함의 비율, 이미지 선명도를 점검하세요. 과한 애니메이션과 불필요한 슬라이더 라이브러리는 추가하지 마세요.
- 기존 앱 방식에 맞춰 페이지 제목, heading 구조, 이미지 크기를 설정하세요.
- 이미 있는 build·typecheck·lint 명령 중 해당하는 것을 실행하세요. 스크립트나 도구가 없으면 임의로 실행했다고 보고하지 마세요.
- 주요 경로의 직접 접근·새로고침·뒤로가기를 확인하고, 링크와 필터·이미지 전환·FAQ 동작을 검증하세요.
- 가능하면 실제 브라우저에서 PC·모바일 스크린샷을 확인하고 여백·정렬·잘림을 수정하세요. 브라우저 검증이 불가능하면 그 한계를 정확하게 보고하세요.
- 시안 확인만을 위해 테스트 프레임워크나 대규모 자동화 환경을 새로 설치하지 마세요.
